# Galgame 周报文案生成 (weekly-script)

采用“**历史选题样本＋中文成稿范例＋当周事实核实**”流程生成每期 Galgame 周报中文初稿。脚本负责资料解析、本地索引构建与检索、跨文件去重、DOCX 导出与结构核验；调用本技能的智能体负责选题判断、当周事实核实与分条中文写稿，不新增外部模型 API 服务。

历史全文、本地索引和每期运行批次均保存在本地工作目录，技能包自身不携带私人语料库。

## 参考文档

执行前按需读取以下参考说明：

- [文风与写作指南](references/style-guide.md)：三栏结构、“说人话”自然口播规范、公式化参考骨架与语病检查底线。
- [选题、合并与核实规则](references/selection-rules.md)：入选标准、同作合并/分条原则、排除项、平台/语言/价格核实清单及输入缺失处理。
- [分类成稿范例](references/category-examples.md)：新作发表、制作完成、体验版、官网更新、主机移植、正式发售、汉化、周边等标准范例与背景边界示例。
- [计划与输出规范](references/output-spec.md)：`draft_plan.json` 结构、`周报初稿.docx`（15 磅加粗标题 / 11 磅常规正文）及四件套产物约定。

## 命令入口

入口脚本：`python '<skill>/scripts/script.py'`。将 `<skill>` 替换为本技能目录的绝对路径，所有路径均传绝对路径。

### 1. 环境诊断与本地索引构建

首次运行或本地新增往期资料后，先诊断并构建/更新三个本地索引（`selection_index.json`、`style_examples.json`、`works_index.json`）：

```powershell
python '<skill>/scripts/script.py' doctor --reports-dir '<weekly_reports目录>' --drafts-dir '<中文成稿目录>' --index-dir '<本地索引目录>'
python '<skill>/scripts/script.py' build-index --reports-dir '<weekly_reports目录>' --drafts-dir '<中文成稿目录>' --output '<本地索引目录>'
```

- 索引构建通过推文 `status_id` 与正文对齐往期分类素材、X 汇总与中文成稿，**绝不按文件后缀数字猜测期号**。
- 自动识别只含标题一行的空 X 汇总文件（标记为 `input_missing_title_only`），不会当作“当周无新闻”。

### 2. 输入检查、推文解析与去重 (`prepare`)

每期生成必须提供**明确的期号**和**明确的报道起止日期**，加上一份或多份 X 汇总 DOCX（可附人工补充素材 DOCX）。期号或日期不明确时先向用户询问，禁止凭文件排序猜测。

```powershell
python '<skill>/scripts/script.py' prepare --issue '<期号>' --date-range '<起止日期>' --x-docx '<X汇总1.docx>' '<X汇总2.docx>' --index-dir '<本地索引目录>' --output '<运行批次根目录>'
```

若进行历史回放或留出测试（如测试第 263、267 期），必须加上 `--max-issue <上一期号>` 或 `--exclude-issue <测试期号>`，防止读取目标期或未来期资料。

`prepare` 会在 `<output>/issue_<期号>_<时间戳>` 创建独立批次目录（避免覆盖旧稿），并输出：
- `input_audit.json`：输入文件覆盖统计、仅含标题的空文件警告、跨文件去重条数。
  - 若**全部输入仅含标题**，状态设为 `empty_input_blocked`，立即停止生成正文并向用户报告输入缺失。
  - 若**部分文件仅含标题**，状态设为 `partial_input_missing`，后续在审阅清单中显著标注覆盖不完整。
- `parsed_tweets.json`：保留账号、发布时间、原创/转发类型、原推文发布时间、正文、展开链接、原文件段落位置；按 `status_id` 去重，自动切分粘连在同一段落的多条推文，并按同账号同作品生成 `candidate_clusters` 聚类提示及 `old_retweet_warning`、`image_only_warning` 标记。

### 3. 背景检索与文风范例检索 (`retrieve`)

阅读 `parsed_tweets.json` 筛选出本周候选事件后，按作品名、品牌、X 账号或事件类型检索本地索引，无需每次读取全部历史文档：

```powershell
python '<skill>/scripts/script.py' retrieve --index-dir '<本地索引目录>' --query '<作品名或品牌>' --event-type '<事件类型>' --section '<新作|汉化|周边>'
```

- 若处于留出测试，必须同样传入 `--max-issue` 和 `--exclude-issue`。
- **事实边界规则**：
  - 本周发生的新变化（如新 CG、体验版公开、预约开启、制作完成）必须来自**本周输入推文或人工补充素材**。
  - 检索到的作品背景（原版发售日、原画/剧本阵容、系列前作关系）须核实后补充，**严禁把范例中的其他作品背景直接套进新稿，也严禁将历史线索当作“本周新发生”的事实**。
  - 索引中标记为 `verification_clue_only: true` 的历史发售日、价格、语言支持仅作核实线索。

### 4. 选题、当周事实核实与写稿 (`draft_plan.json`)

智能体按以下规则完成选题、核实与写稿，并将结果写入 `<run_dir>/draft_plan.json`（格式见 [计划与输出规范](references/output-spec.md)）：

1. **选题与归类**：
   - 沿用三栏：`新作`、`汉化`、`周边`。
   - 保留重大进展（新作公开、官网公开、预约开启、发售日决定、体验版、制作完成、正式发售、主机移植、官中/Steam商店公开、重要周边/展会/联动咖啡/众筹），同时保留往期常选的 CG、CV、OP、角色介绍、背景图等常规更新。
   - 排除无新增信息的反复宣传、倒计时、常规抽奖转发、日常闲聊及无关内容；将未入选的主要候选事件与具体排除理由记录到 `excluded_events`。
2. **当周事实核实**：
   - 只对候选入选事件核查原推文、官方网站、发行商及商店页面（Steam / Nintendo Store / PS Store / BOOTH 等）。
   - 逐项核实**平台、版本（盒装/下载/限定版）、语言支持、具体日期、价格和税别（含税/未税/首发折扣）**。
   - 严禁把英文发行或海外版误写成“官方中文”；严禁把开启预约或公开商店页误写成“正式发售”。
   - **缺失处理**：次要字段（如未公布的具体售价或配角 CV）无法核实时直接省略并在 `omitted_secondary_fields` 记录，不强行编造；核心事件无法确认（如仅有图片提示且官网未同步）则不写入正文，转入 `pending_verifications` 待核实清单。
3. **分条写稿（注意“说人话”＋语病自检）**：
   - 正文遵循：**本周的新变化 → 必要的作品背景 → 发售、预约或活动信息 → 简短引导语**，参考 [文风与写作指南](references/style-guide.md) 中的新作/汉化/周边骨架填空后，务必顺成自然流畅的中文口语，**不要机翻腔（如“锐意制作中”）、不要空洞套话（如“沉浸式体验”）、不要一逗到底的 80 字长句**，同一段落内不重复使用“公开了……并公开了……”。
   - 同作品同一事件的多个来源推文合并为一条并汇总来源链接；同一作品若在本周有两项独立重大进展（如既公开新主视觉又开启众筹活动）则分条表达。
   - 严禁添加 `#作者#` 署名标签、编辑批注或残留未翻译的日文宣传口号。

### 5. 导出双稿产物与全稿结构核验 (`render` & `verify`)

写好 `<run_dir>/draft_plan.json` 后，执行导出与机器核验：

```powershell
python '<skill>/scripts/script.py' render '<run_dir>'
python '<skill>/scripts/script.py' verify '<run_dir>'
```

`render` 会在 `<run_dir>` 下生成四个纯净交付文件并自动调用 `verify`：
1. `周报初稿.docx`：三栏、新闻标题（显式 **15 磅加粗** `w:sz=30`）、正文（**11 磅常规** `w:sz=22`）和独立来源链接段落（**11 磅常规**且附超链接关系），100% 兼容现有 `galgame_news` 的 `DocxDocumentParser`（用于图文排版与归档）。
2. `口播稿.md`：同版三栏纯净正文（无注音底稿），去除所有 URL 链接与编辑信息；需要口播日文罗马音注音时，请将 `周报初稿.docx` 或本文件交给独立的 `weekly-ruby` 技能生成 `口播注音稿.md`。
3. `审阅清单.md`：包含输入覆盖（及空文件/缺失说明）、入选新闻与选题理由、待核实事项清单，以及未入选事件与排除理由。
4. `evidence.json`：每条新闻的来源推文 ID、外部链接、当周事实依据、核实字段、省略字段、引用过的历史期次与范例编号。

只有当 `verify` 返回 `"status": "verified"`（确认 DOCX 解析条数、栏目、标题、链接与计划完全一致，无 `#作者#` 标签、无重复报道推文 ID、无留出期次越界引用）时，才可向用户交付初稿与审阅清单。


## 人工成稿对齐五条硬性准则（基于第 259—267 期对比总结）

1. **月末新作集中发售必合并为首条《X月新作本周发售》**：当 `input_audit.json` 中 `monthly_release_roundup_hint.applicable == true`（即当周覆盖当月最后一个周五集中发售日）时，「新作」栏首条必须合并列出所有当周发售的 PC 与主机作品（`《作品名》（PC/NS）品牌名`），不再将已列入汇总的常规发售作品拆分为独立长条新闻。
2. **三栏配比与周边扩容**：保留追踪作品的常规 1—2 张 CG / 试听语音 / 背景图小更新（采用两句 120—160 字简讯模板）；大幅提高「周边」栏目的召回率（单期常见 7—20 条），重点纳入比例手办/粘土人（`@figsoku` / `@gsc_goodsmile` / MAGI ARTS）、角色抱枕套、付费在线抽赏（`オンラインくじ`）、厂商季节性通贩/复刻再贩（CUFFS / HULOTTE / Lump of Sugar 等）、联动咖啡厅及角色歌/OST/ASMR；排除非核心美少女 Galgame 的传统 JRPG（如《Fate/EXTRA Record》）或纯 VTuber 主演小品。
3. **单句短标题与常用译名优先**：标题严格采用“**主体 + 单一核心动作**”（如 `《Happy Weekend》体验版公开`、`《覗怪》官网公开`），不使用逗号或“公开A并宣布B”双谓语长句；若作品已有广为人知的官方中文名、通行译名或英文名（如《夏日终焉》《咲夜叙-妖刀的约定-》《战国兰斯》《樱花云＊绯红恋》《甜蜜女友3》《爱上火车-Last Run!!》《One Night After》《LimeLight Lemonade Jam》），优先使用中文译名或英文名。
4. **“本周，”统一开篇与简洁收尾**：除“民间汉化发布”与“X月新作本周发售”外，所有新闻正文统一以 **`本周，{品牌/厂商/社团}...`** 起笔，严禁使用 `9月28日，`、`10月2日，` 等具体日期起笔；收尾统一使用 `感兴趣的玩家可以前往官网了解详情 / 持续关注 / 前往 Steam 商店页面购买支持`。
5. **汉化与周边关键数字必填**：汉化栏须写清原作发售年月、原画剧本主创、支持语言及 Steam 国区人民币售价/首发折扣（或锁国区/未公开）；周边栏须写清含税价格区间（`从 XXX 日元至 XXXXX 日元不等（均含税）`）、满额/点单特典门槛、活动或预约起止日期及预计出货月份。
