# 选题、事件合并与事实核实规则

## 一、入选与排除标准

### 1. 优先入选事件与三栏配比校准（基于第 259—267 期人工成稿对比）
- **三栏均衡与周边扩容**：
  - 往期成稿中「周边」栏目占比普遍较高（单期常见 **7—20 条**，与「新作」相当甚至更高），切勿把「周边」硬性压缩在 5—7 条以内而漏掉手办、通贩和抽赏。
- **新作栏（核心节点 + 常规小更新并重）**：
  - **月末新作集中发售必合并为首条《X月新作本周发售》**：若当周覆盖当月最后一个周五（日本 PC Galgame 集中发售日，如 9 月 25 日、10 月 30 日，`input_audit.json` 中 `monthly_release_roundup_hint.applicable == true`），必须在「新作」第一条使用固定格式列出所有本周发售的 PC/主机作品（`《作品名》（PC/NS）品牌名`），**严禁再把已列入汇总的常规发售作品重复拆写成多条独立「正式发售」长文**（同时也不要把同日发售的普通日版或纯文本更新重复塞进其他栏目）。
  - **大节点**：新作首次发表、概念/预告官网公开、正式官网公开、发售日决定、开启预约/预订、商店页面（Steam / eShop / PS Store / DLsite）公开、体验版公开、制作完成（Master Up）、主机移植发表/预约/发售、重制版发表。
  - **常规小更新（往期必选，切勿因篇幅短而漏选）**：官网新增 **1—2 张事件 CG / 样品 CG**、**重制版先行背景图（如《Sentimental Graffiti Remake》公开 4 张背景图）**、公开 OP/ED 动画、宣传 PV、角色试听语音（Sample Voice）。此类常规更新采用 **2 句话精简短模板（约 120—160 字）** 即可，既保证覆盖度又不注水。
- **汉化栏**：
  - 海外发行商（Shiravune、Kagami Games、NekoNyan、Hikari Field 等）宣布官方中文版、公开 Steam 商店页、公布发售日或正式发售；
  - 经典或同人作品民间汉化发布（若人工补充素材或 VNDB 提供了本周汉化记录）。
- **周边栏（7 大高频必选品类）**：
  1. **手办与粘土人**：比例手办企划发表（`フィギュア化決定`）、灰模/彩色原型公开、开启预约、再贩预约、GSC 粘土人（`ねんどろいど`）及 `POP UP PARADE`（常由 `@figsoku`、`@figsoku_b`、`@gsc_goodsmile`、MAGI ARTS、FURYU 等发布）；
  2. **玩偶与抱枕套**：CranCrown / ぬいぐるみ毛绒玩偶（新品或再贩）、各大厂牌（Yuzusoft、あざらしそふと、MOONSTONE 等）角色抱枕套（`抱き枕カバー`）预约或再贩；
  3. **付费在线抽赏（Online Kuji）**：FANZA オンラインくじ、Bunny Club、くじ引き堂等推出的**付费在线抽赏活动**（公布 S/A~E 赏阵容、单抽价格与中奖率），注意将其与免费转发抽奖区分开；
  4. **厂商季节性通贩与复刻再贩**：如 CUFFS、HULOTTE、Lump of Sugar、August 等举办的“残暑通贩 / 秋季通贩 / 周年纪念通贩 & 复刻再贩”、NEXTON「美少女コレクション」插画周边、ゲツオシマート / ドワンゴジェイピーストア主题周边、卡牌周边（牌盒/牌垫/牌套）；
  5. **联动咖啡厅与线下/线上展销**：秋叶原 White&CrossLoad、Cure Maid Cafe、Cafe ASAN、AKIHABARA BENTO 等联动咖啡厅（公布举办决定或公开具体餐点菜单）、快闪店（POP UP SHOP）、澡堂联动、上海 WePlay 等展会参展；
  6. **音乐、广播剧与 ASMR**：游戏 OST 原声带流媒体上架/CD 发售、角色歌合集（キャラソン）、十周年纪念合辑、DLsite 发售的 Galgame 角色 ASMR 音声作品、官方广播节目开播；
  7. **衍生小说、设定集与游戏联动**：官方短篇小说连载、衍生轻小说发售、与《千年戦争アイギス》等页游/手游的角色联动活动。

### 2. 应当排除的内容（防范误选与过度选稿）
- **非核心美少女 Galgame 的泛二次元/主机大作或纯 VTuber 企划**：
  - 排除传统全年龄 JRPG（如 TYPE-MOON《Fate/EXTRA Record》）、纯 VTuber 粉丝向小品（如 ENTERGRAM 主打 hololive / 主播本人的《コヨリニウム》《あじゅ～るメモリア》《君色パトラIF》等，除非人工明确指定收录）、纯三次元硬件/机能风传感器配件等边缘内容。
- **已并入《X月新作本周发售》的同日发售推文**：
  - 月末集中发售日当天，各厂商发布的“本日发售！”推文统一归入首条《X月新作本周发售》名单，不再单独写成独立新闻条目。
- **微小包装工艺或非关键宣发**：
  - 单纯公布“限定版采用烫金外盒 + CERO 评级确认”等琐碎工艺细节，若无官网大更新或体验版/制作完成配合，不单独成条。
- **无新增事实的反复宣传与免费转发抽奖**：
  - 已发售游戏的日常推销、倒计时（“距离发售还有 3 天”）且无新 CG 披露；
  - 单纯要求“关注+转发（フォロー&RP）”抽签字色纸或礼品卡的免费互动抽奖（注意：**若转发抽奖推文中同时写明“官网画廊追加了 1—2 张新 CG / 新增试听语音”，必须提取其官网更新事实入选新作栏，忽略抽奖部分！**）；
  - `flags.old_retweet_hint == true` 的过期旧闻转发。

> **重要原则**：历史索引中“未入选”的推文或分类条目仅作为选题倾向参考，**不能仅凭某账号或某类消息曾在某期未入选就直接判定为“不相关新闻”**。本期所有排除项均须写入 `draft_plan.json` 的 `excluded_events` 并附上具体理由，供人工在 `审阅清单.md` 中复核。

## 二、去重、合并与分条原则

1. **优先按推文 ID (`status_id`) 去重**：
   - 同一期可能传入多份 X 汇总（如周一至周四汇总 + 周五汇总，或带 `_1` 后缀的补充导出）。`prepare` 会自动按 `status_id` 去重并合并 `source_files`。
2. **同作品同事件多推文合并**：
   - 若同一品牌/作品在本周围绕同一事件发布了多条推文（例如《覗怪》同时发了“官网公开”与“OP动画公开”推文，或多画师/多品牌围绕同一展会发推），应**合并为一条新闻综合叙述**，并将所有关联推文的 `status_id` 与链接一并列入该条目的 `source_urls`。
3. **同作品不同独立进展的处理**：
   - 若同一作品在本周既有“游戏本体/FD 新进展”，又有完全独立的“线下联动咖啡厅/手办/抱枕预约”（分别归属“新作”和“周边”栏目），应分条撰写并归入各自栏目；
   - 若同一品牌在同一周既有常规 CG 更新又有 OP 公开（如《One Night After》同周公开主题曲试听与更新 2 张 CG），可按人工习惯拆成两条短讯或合并说明，若共享推文 ID 须显式设置 `"allow_shared_status_id": true`。

## 三、当周事实核实清单

只对候选入选事件核查原推文、官网、发行商及商店页面，重点核对以下六项：

| 核实维度 | 核实要求与常见陷阱防范 |
| --- | --- |
| **平台 (Platform)** | 区分 PC、Nintendo Switch、Switch 2、PS4、PS5、Steam；注意移植版是单平台还是多平台同步。 |
| **版本 (Edition)** | 区分通常版、限定版/豪华版、盒装实体版（パッケージ版）、数字下载版（DL版）。 |
| **语言 (Language)** | 海外发行商（Shiravune、Kagami Games 等）发布 Steam 新闻时，必须核实是否包含简繁中文；若仅宣布英文版，不得写成“官中”。 |
| **日期 (Date)** | 区分“开启预约日”、“体验版公开日”与“正式发售日”；注意日本时区与太平洋时间（PDT）换算导致的日期差异。 |
| **价格 (Price)** | 核对具体日元/人民币金额及首发折扣比例（如“预约期间享 9 折 / 10% OFF”）。 |
| **税别 (Tax)** | 明确价格为含税（税込）还是未税（税別），不可混淆。 |

## 四、输入缺失与待核实事项处理

1. **空文件 / 仅含标题文件**：
   - 当 X 汇总 DOCX 只有首行 `Auto-X-tweets(...)` 而无任何推文记录时，`prepare` 会将其识别为 `input_missing_title_only`。
   - **若全部输入均仅含标题**：停止生成正文，直接报告输入缺失，严禁编造或当作“本周无新闻”。
   - **若部分输入仅含标题**（例如周四至周五的补充文件为空）：正常处理已有文件，但必须在 `审阅清单.md` 第一节醒目标注缺失的文件与时间段。
2. **来源覆盖缺口说明**：
   - X 汇总不一定覆盖全部选题（如部分转发推文、Bilibili 官中视频、VNDB 记录或人工补录）。回放评估时，只针对测试输入实际覆盖的事件评估选题准确率，将输入未覆盖的事件单独列为“来源缺口”。
3. **字段缺失与核心存疑**：
   - **次要字段无法核实**：直接省略该字段，写入 `omitted_secondary_fields`。
   - **核心事件无法确认**（例如推文仅有“更新了！”配一张图，且无文字说明具体更新内容、官网也无法确认）：不写入正式正文，将其列入 `pending_verifications`，交由人工审阅确认。
